Build readiness

Build readiness describes how much of a practical data-use path has been checked and what preparation is still needed. It is separate from the access status, which may record only a page or metadata check.

Workflow tested
A specific documented use case has been reproduced with a representative input, checked output and known limitations. It does not promise that every possible integration works.
Structured sample tested
A structured query or download returned a sample with expected fields. Filtering, joins, geometry, pagination or bulk use may still need testing.
Preparation needed
The inspected source needs documented collection, extraction, cleanup or validation before the intended use. The entry explains the work.
Not yet assessed
Evidence is insufficient to determine a usable build path or the preparation required. This does not mean the data is unusable.

An API, CLI or MCP server is an access method, not proof of good data. PDFs can contain extractable tables or scanned images; inspect an actual file before deciding whether OCR is needed.

Keeping assessments current

Each record includes an assessment date, next review date, evidence and a review owner. The site flags overdue reviews, and a weekly repository check reports them. A maintainer must perform a fresh check before changing the assessment or dates. The system does not automatically reverify city data or improve a rating.

All labels remain subject to the entry’s limitations, freshness, costs and reuse terms. A successful sample does not prove completeness or accuracy.
