# Parcel data pilot

This pilot starts from an official New Haven parcel record. It queries public sources at request time and caches successful lookups for five minutes using Vercel Runtime Cache, with an in-process fallback for local development. It does not store a parcel dataset or source history. Its one stored source table is a dated, validated export of the official NHPS attendance-zone directory, used only when the live school lookup fails and the export is under 30 days old. The static directory remains public; the pilot page, REST routes and MCP endpoint require private access.

## Run and configure

Use Node.js 24. Run `npm ci`, `npm test`, and `npm run build`. For a local Vercel preview, set the variables below in `.env.local` and run `npx vercel dev` in a linked Vercel project. Do not commit the env file.

| Variable | Use |
| --- | --- |
| `PILOT_PASSPHRASE` | Shared passcode for the `/parcel` browser login. |
| `PILOT_COOKIE_SECRET` | Signs seven-day, secure, HTTP-only pilot cookies. |
| `PILOT_API_TOKEN` | Bearer token for API clients and MCP clients. |
| `PILOT_API_KEYS` | Optional JSON array of invited client IDs and SHA-256 token hashes. |
| `PILOT_DISABLE_SHARED_TOKEN` | Set to `1` after individual keys work to revoke the shared API token. |

Each value must contain at least 24 characters. Configure all three as sensitive Vercel environment variables before testing a deployed preview. The endpoints fail closed when any value is missing. Rotate the passcode and token after the pilot; changing the cookie secret invalidates active browser sessions. The browser and API use the same private access policy, while MCP requires the bearer token. Do not put the bearer token in the browser page or a public client configuration.

For the invited pilot, generate one random token per person and store only its SHA-256 hash in `PILOT_API_KEYS`. Example entry: `[{"id":"reviewer_1","sha256":"<64 lowercase hex characters>","active":true}]`. Generate a token with `node -e 'console.log(require("node:crypto").randomBytes(32).toString("base64url"))'` and calculate its hash locally with `node -e 'console.log(require("node:crypto").createHash("sha256").update(process.argv[1]).digest("hex"))' '<token>'`. Share the raw token privately with that reviewer and never commit it. Set `active` to `false` or remove the entry, then redeploy, to revoke access. Once clients have moved to their own keys, set `PILOT_DISABLE_SHARED_TOKEN=1` and redeploy. The shared token remains required as an existing configuration value for now, even while disabled. Runtime logs include route, status and client ID, without parcel queries or tokens.

After adding or changing Vercel variables, create a new deployment for the selected environment; an existing deployment keeps its original environment snapshot. For a branch-specific Preview pilot, scope all three values to the same Git branch.

For any wider rollout, add rate limits at the deployment edge and review the access terms and request budgets of each upstream source. This pilot uses bounded request sizes, timeouts, fixed upstream hosts, and a short cache; it is not a bulk downloader.

## Review flow

Open `/parcel`, enter the pilot passcode, and search by address, parcel ID, MBLU or assessor account number. If a query yields multiple parcel records, choose an official parcel ID and object ID. The review page shows the selected City parcel boundary, a source-linked overview, a dated timeline, and seven groups of readable records. The overview checks the groups and reports their returned counts and source gaps. Opening a group requests its rows; the timeline is requested when opened. One group is visible at a time. Each record row links to its official source, shows key fields, and can reveal all returned source fields. Activity and Business show the source's Permit, License, Application, Complaint, Certificate, Occupant, Contact and Document categories first, then group rows within each category by published status and date for reading. Ownership separates City and assessor owner names, the matched State owner LLC and its registry roles, and published sale and ownership history. These owner rows are not classified as occupants. Source coverage retains returned counts and missing or truncated categories. An open record does not establish a future schedule, an issued permit does not establish work underway, and an occupant row does not establish current operation. The URL preserves a selected parcel ID and object ID; for a verified street-address search it also preserves the searched address, which is checked again against the City resolver on reload.

The selected group and its filters are also saved in the URL. Group and timeline filters cover source category, exact published permit/application/license type, official source, exact published status, inclusive event-date range, and explicit source-address match when a verified address search is active. Group filters additionally cover the display reading group. Counts and facets describe records returned by the checked sources; they are calculated before filters and pagination, so partial and unavailable checks remain visible. A date range excludes undated rows. Changing filters resets pagination. Permit and application rows open a focused detail view with separately labeled public fees, review tasks, inspections, documents, contact roles and other child rows. Contact rows have no event date: the municipal service's `Modified` and `CreatedDate` metadata does not establish when a person held a role. Contacts stay available in Activity and in permit/application details but do not appear as dated timeline events. The protected **Data guide** tab reads the same method, filter, field and source metadata exposed by `GET /api/v1/schema` and MCP resource `newhaven://parcel/schema`. Its live examples run only when requested. The guide and records remain within the private preview.

In Search records, a left navigation stays alongside the parcel review and switches between Overview, Timeline and each record group. It shows returned row counts from the overview, and the Timeline count appears when the timeline is requested. Counts can overlap across groups and describe the current source response. The selected City parcel map appears in Overview. A separate address-level NHPS School Choice result is visible near the parcel heading, with the searched address first when it has an exact match; other parcel addresses and full source records remain accessible. Choosing a record group presents that group's records and filters directly beside the navigation. On narrow screens, a labeled section picker replaces the long navigation strip; the map browser uses the same picker on narrow screens.

The record review starts with all returned statuses, including closed, voided, expired and older records. Activity and Business put recently source-reported open or issued rows first within each category, while exact published statuses remain on each record. Older rows remain available through Load more or by selecting a category. Category controls and visible work-type, published-status and source-address filters narrow the returned rows; More filters retains multi-select category, type, source, reading group and status controls plus date range. Filter chips and Clear all reverse the selection. The timeline has its own visible category, work-type and published-status controls. A section reports how many matching rows are shown and how many rows its checked sources returned before filtering. Category headings appear only after a row in that category has loaded, while the category controls retain pre-filter counts and can request that category directly.

After selecting a parcel, the page draws its [City GIS parcel boundary](https://gis.newhavenct.gov/server/rest/services/Hosted/New_Haven_Parcels_Authoritative_Parcel_Viewer/FeatureServer/0) over the default [Esri street map](https://server.arcgisonline.com/ArcGIS/rest/services/World_Street_Map/MapServer). A map control switches to [Connecticut's 2023 aerial imagery](https://maps.cteco.uconn.edu/data/flight2023/). The boundary is not a building footprint. These backgrounds are visual context, not parcel records or evidence of current conditions. If tiles fail, the selected polygon remains visible on a plain background. An ambiguous search has no map until a parcel is selected.

The **Browse parcel map** tab requests bounded viewport polygons from the official City parcel GIS layer only after the tab opens. At zoom levels below 17, it does not query polygons. Selecting one shows its published parcel ID and address and requests only a verified photo; it does not fetch grouped parcel records or the timeline. **Request parcel data** runs the full parcel lookup in the same browse panel and adds the selected City boundary, on-parcel address points and zoning, and nearby map layers to the same map. At a glance, the timeline, all record groups, source coverage, and load-more controls remain available in that panel. Selecting another polygon hides the previous parcel’s records until its request button is pressed. The photo endpoint confirms the exact City parcel ID and object ID. It first requires one municipal Parcel_ID with an exact PrintKey-to-MBLU match and a JPEG response from the corresponding municipal media path. If that cannot supply a photo, it checks a matching City assessor card PID for a published building image. Street-view and building photos have no published date here and may not show the entire parcel. The browser loads source images directly; none are stored in this project. See the [photo source audit](source-field-audits/parcel-photos.md).

The browsing view uses the full page width, with a left panel that stays visible while the map is panned. The panel contains the selected parcel's published identity, verified photo, source link, request button, map layer controls, and returned records. It can be widened for reading. The default street background is Esri's public tiled [World Street Map](https://server.arcgisonline.com/ArcGIS/rest/services/World_Street_Map/MapServer); an individual New Haven tile returned an image and the service reports a tiled cache through level 23. CT ECO 2023 aerial imagery remains available in the map switcher. The City's Basemapping folders require a token, and the checked public CT ECO map folder did not contain a street basemap. Street and aerial backgrounds are cartographic context; all parcel polygons, identifiers, and records come from the official City or State sources listed separately.

The resolver checks the city's parcel-address field and matching city address points for every street-address search. It intersects address-point coordinates with parcel polygons, so a building address can surface a parcel whose listed address differs from the search. That difference is labeled on the candidate; the resolver does not silently choose between parcels. Address-point association is spatial evidence, not proof of a legal address. It preserves every zoning polygon returned for a parcel. Parcel geometry is returned in longitude and latitude for intersections. No manually supplied address aliases are used.

The Property group also checks the City's [trash pickup day polygon view](https://gis.newhavenct.gov/server/rest/services/Hosted/Trash_Pickup_Day_%28View%29/FeatureServer/0) against City address points on the parcel. It returns one address-level record only when exactly one City pickup zone contains that address point. The City layer last reported an edit on July 3, 2025 during the November 17, 2026 source check; each live result reports the layer's current published edit date. A zone record says which weekday the City maps at that address point, not whether a particular business receives City collection or whether a holiday changes the pickup day. [City Public Works](https://www.newhavenct.gov/government/departments-divisions/public-works-department/trash-recycling) supplies service and schedule guidance. No zone geometry or address-to-zone association is stored in this project.

The Property group and MCP now return an address-level NHPS K–8 and high-school attendance-zone record when an official City parcel address or intersecting City address point matches an exact [NHPS street and house-number range](https://www.newhavenmagnetschools.com/index.php/enrollment/find-schools-in-your-attendance-zone). Published odd/even limits are applied. The original street, range, school names and NHPS row IDs remain in the record. An address with a gap or conflicting ranges receives no school assignment. NHPS says the zones give residents preference during the School Choice Placement Process; a zone does not guarantee placement or identify a student's current school. The City's Board of Education district GIS layers are electoral districts and are not used for this join.

The adapter posts a street search to NHPS for each distinct City-listed street and checks the returned row against the exact address. If the live NHPS site fails or its table structure changes, it can use the official NHPS spreadsheet export saved in `data/nhps-attendance.json` only while its `retrieved_at` is within 30 days. Fallback records show the snapshot date and the live failure reason; older snapshots are rejected. The snapshot was extracted from the official catalog's alphabet-filtered XLSX exports and validated against its published total, with a SHA-256 of the normalized rows. Run `python3 scripts/refresh-nhps-attendance.py` to refresh it. The weekly GitHub workflow is scoped to the private `codex/parcel-pilot` branch and starts running on its schedule once the workflow file is on the repository's default branch; the live lookup provides current-source checks in the preview meanwhile. No school attendance GIS boundary or manually inferred assignment is used.

The parcel-address route requires an exact returned address. This prevents a search for `3 Edwards St` from listing `30`, `34` or `360 Edwards St` ahead of the address-point parcel. In the live source, the `3 Edwards St` address point intersects parcel 10386, whose official parcel address is `990 State St`. That relationship is shown as a spatial candidate; it is not an assertion that every business using 3 Edwards occupied the parcel.

An address search remains visible as an address focus after parcel selection. Record and timeline badges say “Source address matches search” only when the returned record itself has a full address field that matches the query after street suffix and punctuation normalization. Eligible fields are the City parcel's `property_address`, City address-point number and street, the City address point used for a trash zone or NHPS street-range join, municipal `LegalAddress` on a permit, application, license, certificate, complaint or occupant, the State brownfield row's published site address, and the site-address field of a linked State liquor, child care or cannabis record. A municipal `Addr1` or generic `Address` field, free-text description, parcel MBLU, assessor row, and spatial proximity alone do not produce that badge. Rows without a badge remain visible as parcel-linked records; lack of a badge does not establish that they are unrelated to the searched storefront. For example, a `3 Edwards St` search can show the City address point badge while the Bar August license rows naming `990 State St` remain parcel records without that badge.

## REST API

Send `Authorization: Bearer <PILOT_API_TOKEN>` from a private client. A signed browser session cookie also works for REST. Responses use `Cache-Control: private, no-store` even though upstream lookups are cached inside the server. Failed sources are reported per source so a missing result is distinguishable from an unavailable source.

| Route | Purpose |
| --- | --- |
| `POST /api/v1/resolve` with JSON `{"query":"165 Church Street"}` | Resolve to zero, one, or multiple official parcel candidates. |
| `GET /api/v1/parcel?parcel_id=...&objectid=...` | Selected parcel identity and available groups. |
| `GET /api/v1/geometry?parcel_id=...&objectid=...` | Verified selected parcel boundary as a GeoJSON Feature, with bounding box, source link and identifiers. |
| `GET /api/v1/map-context?parcel_id=...&objectid=...` | Official mapped features on the parcel plus nearby access features, each with a source, status and GeoJSON geometry. |
| `GET /api/v1/overview?parcel_id=...&objectid=...` | Compact counts, source statuses and five recent dated record references. |
| `GET /api/v1/records?parcel_id=...&objectid=...&group=property&limit=25&cursor=...` | One filtered, paginated group of source records, source statuses and pre-filter facets. |
| `GET /api/v1/trash-pickup?parcel_id=...&objectid=...&query_address=...` | Address-point pickup zone records, City source edit date, source status and optional search-address match flags. |
| `GET /api/v1/school-attendance?parcel_id=...&objectid=...&query_address=...` | NHPS K–8 and high-school School Choice attendance-zone schools for exact City-listed addresses, with live or official-snapshot provenance and optional address focus. |
| `GET /api/v1/feed?parcel_id=...&objectid=...&limit=25&cursor=...` | Filtered dated source records, newest first. |
| `GET /api/v1/permit-details?parcel_id=...&permit_id=...` and `GET /api/v1/application-details?parcel_id=...&application_id=...` | Public child rows and source fields for an exact municipal work ID on the selected parcel. |
| `GET /api/v1/schema` | Protected method, filter, field and official source guide. |
| `GET /api/v1/permit-types` | Live City permit type catalog, grouped by its published `TypeGroup`. These are configured type names, not counts of issued permits. |
| `GET /api/v1/sources` | Source catalog, modes, limitations and deliberate exclusions. |

`objectid` is required when an official `parcel_id` maps to more than one source feature. Page size is capped at 50. Each record carries its source ID, source record ID, fields, match method, source URL, source event date where known, and retrieval time. Municipal and LCI records also expose the official identifier fields used for their parcel match; LCI requires the property address to match as well. The feed contains dated source records; it does not detect changes between requests. The API does not claim that an empty source response proves that no event exists. Vacancy status is handled outside this data layer. One-off reports and studies are not source resources in this pilot.

For Ownership, Business and Activity, `GET /api/v1/records` and the matching MCP tool return `display_groups`, `display_group_counts`, and an item `display_group` with `key`, `basis`, and `as_of`. Ownership is sorted as published owner names, matched LLC registry roles, then assessor ownership history. Business and Activity are sorted before paging so reported current records precede drafts, older records, voided or expired records, and records with no recognized status. A record with a nonterminal source status and a dated event more than two years old goes into “older,” without being declared closed; a reported issued license with a published future expiration stays in the reported section. A license with a published expiration before `as_of` goes into “past,” even when the source still says “Issued.” An occupant lacking an explicit inactive flag remains unclassified. The original source status and dates remain in `attributes`; this display grouping is not a verified determination of present operation, permit completion, or vacancy. The dated feed remains chronological and includes the same display group on relevant activity rows.

`GET /api/v1/records` and `GET /api/v1/feed` accept repeatable `category`, `record_type`, `source_id` and `source_status` filters, inclusive `event_date_from` and `event_date_to`, and `address_match=true` when `query_address` is supplied. Records also accept repeatable `display_group`. `record_type` compares the published permit, application or license type exactly, ignoring case. Each response includes `filters`, `facets`, `total`, `returned_total` and `next_cursor`. Facets and `returned_total` count rows returned by checked sources before filters and paging; `total` counts filtered rows before paging. Keep the same filters with a cursor. These are selected-parcel filters, not a City-wide search.

`GET /api/v1/records`, `GET /api/v1/feed`, `GET /api/v1/trash-pickup`, and `GET /api/v1/school-attendance` accept optional `query_address=<street address>` for address-focus comparison. Each returned item then has `address_evidence`, which is `null` if that source record has no eligible explicit address or an object with `source_field`, `source_address`, and `matches_query`. The comparison does not change parcel association; `address_match=true` deliberately filters to rows with matching explicit source addresses in the two paginated routes. The MCP `get_parcel_records`, `get_parcel_feed`, `get_parcel_trash_pickup`, and `get_parcel_school_attendance` tools accept the same optional `query_address` argument. API clients should resolve the address and select the City parcel first; the browser does this before displaying an address focus.

## MCP

`/mcp` exposes Streamable HTTP MCP with stateless requests and bearer authentication. It registers the matching parcel, geometry, photo, overview, record, feed, trash pickup, map, permit detail, application detail, cross-parcel permit search, municipal permit type catalog and source catalog tools. The protected `newhaven://parcel/schema` resource is the same guide served by REST; source-coverage and matching-method resources remain available. Start with `resolve_parcel`, then `get_parcel_overview`; request geometry, map context or one record group only when needed. The MCP tools call the same service and filters as REST, including ambiguity and partial-source behavior. Point an MCP client at `https://<deployment>/mcp` and send `Authorization: Bearer <individual pilot token>` on each request. Keep this token in the client's private secret store.

## Source coverage

The machine-readable catalog is published in `dist/parcel-source-catalog.json` and returned by `/api/v1/sources`. `live` means the adapter makes a source request when queried; it does not certify source completeness or currentness. `gap` means no direct parcel association has been verified, and the parcel response marks that source `not_integrated` rather than calling it a failed check. `paused` means deliberately excluded from collection for now. A State owner LLC source is `not_linked` when the required official owner match cannot be established. The three State site-location sources are `not_linked` when the City has no address points on the selected parcel or all candidate site addresses fail the unique parcel check. Runtime source errors appear as `unavailable`, and truncated or otherwise incomplete live responses as `partial`; only these two statuses set the group's `partial` flag. Each source and its limitation remain in the response and Source coverage panel. The overview names affected live sources and puts known integration and linkage limits in one expandable list. GIS CMT contact rows are marked partial only if the GIS result is truncated; the separate caution to confirm current contacts remains visible in their coverage. Generic State credentials without a verified site-to-parcel join, address-only State business registry records, and manually selected planning documents are not returned as parcel records.

| Group | Live parcel-linked records | Visible gaps |
| --- | --- | --- |
| Property | The complete selected City parcel attribute row plus its building, use, units and assessed fields; City address points and trash pickup zones joined to address points; Vision assessor land, building, subarea, extra-feature, outbuilding and valuation rows | City parcel assessed columns have no verified valuation year or tax balance. A mapped pickup zone does not establish commercial collection eligibility. Assessment subareas do not establish retail lease area. Tax bill and City Clerk land records still lack a verified parcel join. |
| Ownership | City GIS first and second owner and mailing fields; one City parcel sale field set; separately published assessor owner, co-owner, mailing and Ownership History rows; matched Connecticut owner LLC entity, principals, and registered agent | The City and assessor owner names can differ. A single City sale field set and assessor history may omit transfers. Registry principals and agents do not establish beneficial ownership or direct property title. |
| Geography | City zoning code, district category and districts for every intersecting polygon; wards, neighborhoods, and mapped local and State historic districts | Zoning codes do not describe the square footage allocated to a use. Historic district maps are dated 2022 and 2021 and are general reference, not permit determinations. |
| Environment | Connecticut DEEP brownfields inventory rows with an exact published Site Parcel match to City PID or MBLU | The inventory is a February 2026 snapshot, not a statement of current contamination or a complete environmental site search. |
| Representation | Board of Alders roster through an unambiguous ward; city GIS CMT district intersections and provisional GIS contact fields | CMT contact details can differ from the city CMT page and require confirmation. |
| Activity | Live municipal parcel documents, applications, complaints, contacts, licenses, occupants, permits and certificates; LCI Case HQ case metadata; LCI managed lots | Municipal complaint narratives and personal contact fields are omitted. Planning cases, LCI licensing, and other inspection or enforcement feeds need a verified parcel join. |
| Business | Named municipal license and occupant rows attached to the Municity parcel reached by verified MBLU; State liquor, child care, youth camp and operating cannabis retail location rows joined by site address to City address points and a unique City parcel | A license or occupant row does not establish a current tenant or business operation. Generic State credentials with no verified site field remain a gap. |

Meetings, agendas and legislation, budgets and monthly finance reports, census area context, and records on nearby parcels are outside this pilot's parcel record scope. City hosted transit stops are available only as separately labeled nearby map context. CMT meeting schedules are not collected.

The parcel map uses the selected City parcel polygon. Separate map context layers show City address points and zoning polygons intersecting that parcel, plus City hosted CT Transit stops and City mapped metered parking spaces within 400 metres in a straight line from the center of the parcel's mapped extent. The metered spaces toggle starts off because it can contain many points. When no meter points are returned within 400 metres, its toggle is disabled and the reason is shown. Each layer reports its source and last edit date when the service publishes one. A failed layer is `unavailable`, not an empty result. These features are not added to parcel record groups or the timeline. The City meter layer is an inventory of mapped points; it does not establish whether a space is open or its current rules or rates. The City publishes [parking maps](https://www.newhavenct.gov/government/departments-divisions/transportation-traffic-parking/resources/maps), but no current machine-readable City or State loading-zone or parking-availability layer has been verified for this pilot. Neither loading-zone markers nor available-space claims are drawn. See the [metered parking source audit](source-field-audits/metered-parking-map.md).

CMT districts are resolved at request time by intersecting the official parcel geometry with the city's CMT district FeatureServer. Every intersecting district is returned; overlapping districts are marked partial rather than selecting one. The same city GIS layer provides manager, neighborhood specialist and chair contact fields. Those contacts are marked provisional because the city's CMT webpage can differ from the GIS layer. No district shapes or contact roster is stored in this project.

Named municipal business licenses are a compact view of the same live Municity parcel children shown in Activity. The verified MBLU links them to the parcel, and the business group preserves the vendor's license status and recorded address. For parcel 10386, this includes `Weary Hobo LLC aka Bar August` with vendor status `Void`, and a `Bar August` license with status `Issued` and a 2023 expiration date. Both records list `990 State St`; neither independently establishes the historical `3 Edwards St` business address or current operation. No business roster or address alias is stored locally.

The Business group counts City License rows whose published `BusinessName` is empty and points to their full rows under Activity → Licenses. It does not label residential licenses as business licenses. The overview distinguishes named license rows from municipal Occupant rows, since an occupant name and occupancy type do not by themselves identify a business. At parcel 11236 (`20 Eld St`), the four currently returned municipal License rows are residential types and none supplies `BusinessName`; they remain visible in Activity's historical section. The official State Business Registry Master lists `All Day Bar Co. LLC` with billing street `20 Eld St`, but that billing address is not a City parcel identifier or evidence that the entity operated at the parcel. Address-only State entity matches are excluded from the parcel Business group.

The Business group also queries three official Connecticut rosters at request time: [liquor permits](https://data.ct.gov/d/gwv2-eswx), [child care and youth camp licenses](https://data.ct.gov/d/h8mr-dn95), and [operating cannabis retail locations](https://data.ct.gov/d/42yd-3x3d). Their site fields are `permit_address`, `address2`, and `street`, respectively. Backer and mailing addresses are preserved as source fields where present but never used to link a parcel. Each site address must exactly match a City address point on the selected parcel after standard street abbreviation and punctuation normalization. The adapter then checks all City address points for that site address and requires every distinct point to intersect only the selected City parcel. An address used on multiple parcels, a point on a parcel boundary, and a missing City address point are not treated as parcel links. A GIS check that exceeds its bounds is marked partial. The State rows publish no City parcel ID, so the record's `match` object states the address-point join and the City point IDs. The source's status, dates, type and full returned fields remain visible; liquor and child care effective dates enter the dated feed. Cannabis roster rows are prioritized as roster-listed operating locations, with no invented row-level status or date. The generic [State Licenses and Credentials](https://data.ct.gov/d/ngch-56tr) dataset remains a catalog gap because its generic address is not a verified site location. No State roster or parcel snapshot is stored locally; successful checks use the same five-minute cache.

The State Licenses and Credentials dataset is official, but credential addresses do not carry a verified New Haven parcel identifier. It remains a gap. The former Keys On Kites address-only association at parcel 24641 remains excluded.

For an LLC named as the City parcel owner, the Ownership group checks the live [Connecticut Business Registry Master](https://data.ct.gov/Business/Connecticut-Business-Registry-Business-Master/n7gp-d28j). It requires the full legal name, billing street (including any unit number), city and five-digit ZIP to match the City parcel's published owner name and mailing fields. Common punctuation, whitespace and street suffix spelling are normalized for comparison. The State result must be unique among the queried literal legal-name variants; if the assessor card is available and names a different owner, the link is blocked. If those results are ambiguous, truncated, time out or have no matching mailing address, all State owner LLC sources are `unavailable` and no State row is attached to the parcel. Other registry spelling variations remain uncovered. State entity status and formation date are entity facts, not a date or proof of parcel acquisition.

Only after that match does the API query the official [State Principals](https://data.ct.gov/Business/Connecticut-Business-Registry-Principals/ka36-64k6) dataset with its published `business_id = Master.id` and the [State Agents](https://data.ct.gov/Business/Connecticut-Business-Registry-Agents/qh2m-n44y) dataset with `business_key = Master.id`. The Agents dataset's older `business_id` is not used for this join. The API exposes principal names and published business-address fields, and separately exposes the registered agent's published service phone, email and business address. It omits agent residence and mailing fields. These are distinct registry roles: a principal can be a member, manager or other listed party, and a registered agent receives service for the LLC. Neither role is relabeled as a beneficial owner or a direct owner of the real estate. At parcel 10386 (990 State St), the current official City and State owner fields match `990 STATE STREET ASSOCIATES, LLC`, ALEI `0659195`; the State currently lists `The Robert Megna Trust` as a principal and `ROBERT MEGNA` as its agent. This example is a live source check, not a locally stored affiliation table. Results are queried on demand with the pilot's five-minute cache.

The city GIS parcel 13791 has the same MBLU and lists `181 CROWN ST`. Municipal permit `B-21-02020` is attached to that parcel and describes work at Cask Republic, with legal address `181 CROWN ST`. Neither that parcel record nor the checked city parcel and address-point layers identifies `179 CROWN ST` as an address for this parcel. The resolver therefore does not attach a search for `179 Crown St` to parcel 13791. Cask Republic appears only in the original municipal work record, not as a parsed business listing.

For parcel 24641, the municipal vendor response omits the Complaint and License categories. Those categories remain labeled “not returned” with unconfirmed counts; the Business group does not claim that no municipal license exists.

The municipal parcel lookup reads Document, Application, Complaint, Contact, License, Occupant, Permit and Certificate arrays from the public vendor response after matching its parcel PrintKey to the city's MBLU. In four checked live parcels, the vendor returned only populated category keys, including both Complaint and Certificate where they had rows. A returned empty array has count zero; an omitted category has count `null` and displays as “not returned.” Omission by itself is not treated as a failed live check or a verified zero. Categories over the 500-record display limit are marked partial; the displayed count covers only returned public records. The response retains `omitted_categories`, `missing_categories` for compatibility, `truncated_categories`, and `category_counts` for API and MCP clients. Public, nondeleted document records include a link to the vendor file when its URL is available on the verified media host. The API does not download or store files. Complaint records omit narrative; contact records omit phone, email and mailing address. Occupant rows expose only name, business name, occupancy type, recorded address, source-reported inactive flag and creation date. Deleted rows and rows with a conflicting Parcel_ID are excluded. A missing inactive flag is not treated as active status. Permit and application child rows expose source-reported status and work description; the on-demand [work detail lookups](source-field-audits/municity-permits.md) follow an exact permit or application ID to full source fields, fees, review tasks, inspections where returned, public documents, contact roles, communication metadata and source flags. A permit includes its explicitly linked application. A returned inspection row does not establish complete inspection coverage. The [cross-source permit search](cross-source-permit-search.md) filters a bounded municipal permit type through City neighborhood geometry and exact parcel MBLU joins, with explicit completeness limits.

The assessor adapter checks the exact PID on the live City of New Haven Vision card before returning any fields. Its Ownership record carries the primary owner, a published co-owner when supplied, and separate mailing-address lines. Its Ownership History table supplies individual owner, sale price, book and page, instrument, certificate and sale date rows. Those rows appear in the Ownership group and, when dated, in the timeline. The City GIS parcel's separate `parcel-sale` record supplies its one published sale date, price, book and page field set. Four assessor valuation tables supply current and historical appraised and assessed rows by valuation year; a valuation year is not converted into an event date. A `$0` sale price is displayed literally, with no market-value interpretation. The same card can publish building count, year built, living area, land size, use code, model, style and stories. Single-building summary facts are extracted only from unique labels; multiple building sections remain separate. Each readable Building Sub-Areas table supplies individual code, description, gross area, living area and its published building section. Totals are excluded from individual rows, and unreadable source values are preserved as published and marked partial. Separate property records carry the card's land-use and land-measure rows, building-section summary and attribute rows, Extra Features rows, and Outbuildings rows. An assessor zone is not a City zoning determination, and a subarea does not by itself establish a retail lease area. Undated assessment facts stay out of the dated timeline. When Vision redirects an exact PID lookup to its own error page, all sections from that card are marked unavailable with the specific reason; the UI summarizes the shared card failure once per group. For City parcel 11236 at 20 Eld St, Vision's exact PID 11236 currently gives that error. Vision's address search shows unit cards, but no verified parent-card join was found, so unit facts are not substituted for the City parcel. The assessor's published rows may not be a complete deed chain. City Clerk land records remain a gap until a direct parcel join is verified. See the [assessor field audit](source-field-audits/assessor.md) and [City parcel field audit](source-field-audits/city-parcels.md) for checked fields and remaining coverage limits.

The City hosted [local historic district](https://services6.arcgis.com/AWSPcxcHO7OnZlnu/ArcGIS/rest/services/New_Haven_Local_Historic_Districts/FeatureServer/5) and [State historic district](https://services6.arcgis.com/AWSPcxcHO7OnZlnu/ArcGIS/rest/services/New_Haven_State_Historic_Districts/FeatureServer/1) polygons are queried by parcel intersection. The [Connecticut DEEP brownfields layer](https://services1.arcgis.com/FjPcSmEFuDYlIdKC/ArcGIS/rest/services/Brownfields_Final_2025/FeatureServer/0) is queried for New Haven rows and then filtered to an exact PID or MBLU match against its published `Site_Parce` field. Address and point proximity never create a brownfield parcel record. These sources are retrieved at request time and share the existing short cache. No historic boundary or DEEP inventory row is turned into a current permit or environmental determination.

LCI is queried at request time by the assessor PID. The adapter requires matching PID and address on the public property page and returns only case number, type, status, filed date, listed case fine, and link. A case section is considered checked only when the page supplies a recognizable table or explicitly says zero cases; missing sections make the response partial, and a page with neither is unavailable. An official HTTP 404 for that PID is `not_linked`: it means the public portal has no page at that identifier, and no zero case count is inferred. Other upstream HTTP errors remain unavailable. It does not fetch case-detail pages, complaint narratives, or attachments. A listed fine is source-reported and should be confirmed before use. The real-estate tax and land-record sources expose links and honest `unavailable` statuses until a permitted live lookup and parcel join are verified. SearchIQS is not scraped. The API stores no parcel dataset or change history. The only stored source table is the dated NHPS attendance-zone fallback; other successful lookups use the existing five-minute runtime cache.

## Verification and limits

`npm test` covers private access, ambiguous parcel IDs, selected polygon conversion including holes and multiple parts, REST/MCP geometry parity, missing and projected geometry, multiple intersecting zoning and historic district records, exact DEEP parcel matching, municipal child categories, assessor building facts and ownership and valuation tables, exclusion of address-only state records, partial feed behavior when an upstream fails, and MCP initialization. `npm run build` validates the original directory and emits the pilot source catalog and locally bundled map library. Public source terms, historical coverage, and field freshness still need source-level review.
