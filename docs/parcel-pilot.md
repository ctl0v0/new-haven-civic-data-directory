# Parcel data pilot

This pilot starts from an official New Haven parcel record. It queries public sources at request time and caches successful lookups for five minutes using Vercel Runtime Cache, with an in-process fallback for local development. It does not store a parcel dataset or source history. The static directory remains public; the pilot page, REST routes and MCP endpoint require private access.

## Run and configure

Use Node.js 24 or later. Run `npm ci`, `npm test`, and `npm run build`. For a local Vercel preview, set the variables below in `.env.local` and run `npx vercel dev` in a linked Vercel project. Do not commit the env file.

| Variable | Use |
| --- | --- |
| `PILOT_PASSPHRASE` | Shared passcode for the `/parcel` browser login. |
| `PILOT_COOKIE_SECRET` | Signs seven-day, secure, HTTP-only pilot cookies. |
| `PILOT_API_TOKEN` | Bearer token for API clients and MCP clients. |
| `PILOT_API_KEYS` | Optional JSON array of invited client IDs and SHA-256 token hashes. |
| `PILOT_DISABLE_SHARED_TOKEN` | Set to `1` after individual keys work to revoke the shared API token. |

Each value must contain at least 24 characters. Configure all three as sensitive Vercel environment variables before testing a deployed preview. The endpoints fail closed when any value is missing. Rotate the passcode and token after the pilot; changing the cookie secret invalidates active browser sessions. The browser and API use the same private access policy, while MCP requires the bearer token. Do not put the bearer token in the browser page or a public client configuration.

For the invited pilot, generate one random token per person and store only its SHA-256 hash in `PILOT_API_KEYS`. Example entry: `[{"id":"reviewer_1","sha256":"<64 lowercase hex characters>","active":true}]`. Generate a token with `node -e 'console.log(require("node:crypto").randomBytes(32).toString("base64url"))'` and calculate its hash locally with `node -e 'console.log(require("node:crypto").createHash("sha256").update(process.argv[1]).digest("hex"))' '<token>'`. Share the raw token privately with that reviewer and never commit it. Set `active` to `false` or remove the entry, then redeploy, to revoke access. Once clients have moved to their own keys, set `PILOT_DISABLE_SHARED_TOKEN=1` and redeploy. The shared token remains required as an existing configuration value for now, even while disabled. Runtime logs include route, status and client ID, without parcel queries or tokens.

After adding or changing Vercel variables, create a new deployment for the selected environment; an existing deployment keeps its original environment snapshot. For a branch-specific Preview pilot, scope all three values to the same Git branch.

For any wider rollout, add rate limits at the deployment edge and review the access terms and request budgets of each upstream source. This pilot uses bounded request sizes, timeouts, fixed upstream hosts, and a short cache; it is not a bulk downloader.

## Review flow

Open `/parcel`, enter the pilot passcode, and search by address, parcel ID, MBLU or assessor account number. If a query yields multiple parcel records, choose an official parcel ID and object ID. The review page shows the selected City parcel boundary, a dated timeline, and seven groups of readable records. “At a glance” is hidden while its content is being defined; the record list uses compact rows for source review. Each record row links to its source, shows key fields, and can reveal all returned fields; each group shows source status and coverage. Business and activity records are ordered into reported active/open/issued, draft/review, older unresolved, closed/void/expired, and other/unstated status sections. Ownership has its own group: City and assessor owner names, one City parcel sale field set, the matched State owner LLC and its registry roles, and assessor ownership history. These are not included in Business. Within each activity section, the source's Permit, License, Application, Complaint, Certificate, Occupant, Contact and Document categories remain distinct; source coverage retains returned counts and missing or truncated categories. LCI activity records have separate source headings. Older and closed sections start collapsed for easier review. Only records linked to the selected parcel are included; neighborhood and nearby records are outside this pilot. An open record does not establish a future schedule, an issued permit does not establish work underway, and an occupant row does not establish current operation. The URL preserves a selected parcel ID and object ID; for a verified street-address search it also preserves the searched address, which is checked again against the City resolver on reload.

After selecting a parcel, the page draws its [City GIS parcel boundary](https://gis.newhavenct.gov/server/rest/services/Hosted/New_Haven_Parcels_Authoritative_Parcel_Viewer/FeatureServer/0) over [Connecticut's 2023 aerial imagery](https://maps.cteco.uconn.edu/data/flight2023/). The boundary is not a building footprint, and the imagery does not establish current occupancy or conditions. The background tiles are visual context, not neighboring parcel records. If the tiles fail, the selected polygon remains visible on a plain background. An ambiguous search has no map until a parcel is selected.

The **Browse parcel map** tab requests bounded viewport polygons from the official City parcel GIS layer only after the tab opens. At zoom levels below 17, it does not query polygons. Selecting one shows its published parcel ID and address and requests only a verified photo; it does not fetch grouped parcel records or the timeline. **Request parcel data** opens the record view and runs the full parcel lookup. The photo endpoint confirms the exact City parcel ID and object ID. It first requires one municipal Parcel_ID with an exact PrintKey-to-MBLU match and a JPEG response from the corresponding municipal media path. If that cannot supply a photo, it checks a matching City assessor card PID for a published building image. Street-view and building photos have no published date here and may not show the entire parcel. The browser loads source images directly; none are stored in this project. See the [photo source audit](source-field-audits/parcel-photos.md).

The resolver checks the city's parcel-address field and matching city address points for every street-address search. It intersects address-point coordinates with parcel polygons, so a building address can surface a parcel whose listed address differs from the search. That difference is labeled on the candidate; the resolver does not silently choose between parcels. Address-point association is spatial evidence, not proof of a legal address. It preserves every zoning polygon returned for a parcel. Parcel geometry is returned in longitude and latitude for intersections. No manually supplied address aliases are used.

The Property group also checks the City's [trash pickup day polygon view](https://gis.newhavenct.gov/server/rest/services/Hosted/Trash_Pickup_Day_%28View%29/FeatureServer/0) against City address points on the parcel. It returns one address-level record only when exactly one City pickup zone contains that address point. The City layer last reported an edit on July 3, 2025 during the November 17, 2026 source check; each live result reports the layer's current published edit date. A zone record says which weekday the City maps at that address point, not whether a particular business receives City collection or whether a holiday changes the pickup day. [City Public Works](https://www.newhavenct.gov/government/departments-divisions/public-works-department/trash-recycling) supplies service and schedule guidance. No zone geometry or address-to-zone association is stored in this project.

School assignment remains an explicit source gap in Property and the MCP source catalog. The two City [Board of Education Districts](https://gis.newhavenct.gov/server/rest/services/Hosted/Board_of_Education_Districts_view/FeatureServer/0) layers publish only District 1 and District 2; the [City Clerk election page](https://www.newhavenct.gov/government/departments-divisions/city-clerk/election-information) confirms these are electoral districts. They cannot identify a zoned school. A live check of the City GIS service catalog found school location layers but no attendance-zone school boundary layer. The official [NHPS attendance-zone lookup](https://www.newhavenmagnetschools.com/index.php/enrollment/find-schools-in-your-attendance-zone) publishes K–8 and high school names by street and house-number range, but returned HTTP 403 to the live backend on November 17, 2026. No cached page, approximate boundary, or manually stored assignment is used.

The parcel-address route requires an exact returned address. This prevents a search for `3 Edwards St` from listing `30`, `34` or `360 Edwards St` ahead of the address-point parcel. In the live source, the `3 Edwards St` address point intersects parcel 10386, whose official parcel address is `990 State St`. That relationship is shown as a spatial candidate; it is not an assertion that every business using 3 Edwards occupied the parcel.

An address search remains visible as an address focus after parcel selection. Record and timeline badges say “Source address matches search” only when the returned record itself has a full address field that matches the query after street suffix and punctuation normalization. Eligible fields are the City parcel's `property_address`, City address-point number and street, the City address point used for a trash zone join, municipal `LegalAddress` on a permit, application, license, certificate, complaint or occupant, and the State brownfield row's published site address. A municipal `Addr1` or generic `Address` field, free-text description, parcel MBLU, assessor row, and spatial proximity alone do not produce that badge. Rows without a badge remain visible as parcel-linked records; lack of a badge does not establish that they are unrelated to the searched storefront. For example, a `3 Edwards St` search can show the City address point badge while the Bar August license rows naming `990 State St` remain parcel records without that badge.

## REST API

Send `Authorization: Bearer <PILOT_API_TOKEN>` from a private client. A signed browser session cookie also works for REST. Responses use `Cache-Control: private, no-store` even though upstream lookups are cached inside the server. Failed sources are reported per source so a missing result is distinguishable from an unavailable source.

| Route | Purpose |
| --- | --- |
| `POST /api/v1/resolve` with JSON `{"query":"165 Church Street"}` | Resolve to zero, one, or multiple official parcel candidates. |
| `GET /api/v1/parcel?parcel_id=...&objectid=...` | Selected parcel identity and available groups. |
| `GET /api/v1/geometry?parcel_id=...&objectid=...` | Verified selected parcel boundary as a GeoJSON Feature, with bounding box, source link and identifiers. |
| `GET /api/v1/map-context?parcel_id=...&objectid=...` | Official mapped features on the parcel plus nearby access features, each with a source, status and GeoJSON geometry. |
| `GET /api/v1/overview?parcel_id=...&objectid=...` | Compact counts, source statuses and five recent dated record references. |
| `GET /api/v1/records?parcel_id=...&objectid=...&group=property&limit=25&cursor=...` | One grouped, paginated page of source records and source statuses. |
| `GET /api/v1/trash-pickup?parcel_id=...&objectid=...&query_address=...` | Address-point pickup zone records, City source edit date, source status and optional search-address match flags. |
| `GET /api/v1/feed?parcel_id=...&objectid=...&limit=25&cursor=...` | Dated source records, newest first. |
| `GET /api/v1/sources` | Source catalog, modes, limitations and deliberate exclusions. |

`objectid` is required when an official `parcel_id` maps to more than one source feature. Page size is capped at 50. Each record carries its source ID, source record ID, fields, match method, source URL, source event date where known, and retrieval time. Municipal and LCI records also expose the official identifier fields used for their parcel match; LCI requires the property address to match as well. The feed contains dated source records; it does not detect changes between requests. The API does not claim that an empty source response proves that no event exists. Vacancy status is handled outside this data layer. One-off reports and studies are not source resources in this pilot.

For Ownership, Business and Activity, `GET /api/v1/records` and the matching MCP tool return `display_groups`, `display_group_counts`, and an item `display_group` with `key`, `basis`, and `as_of`. Ownership is sorted as published owner names, matched LLC registry roles, then assessor ownership history. Business and Activity are sorted before paging so reported current records precede drafts, older records, voided or expired records, and records with no recognized status. A record with a nonterminal source status and a dated event more than two years old goes into “older,” without being declared closed; a reported issued license with a published future expiration stays in the reported section. A license with a published expiration before `as_of` goes into “past,” even when the source still says “Issued.” An occupant lacking an explicit inactive flag remains unclassified. The original source status and dates remain in `attributes`; this display grouping is not a verified determination of present operation, permit completion, or vacancy. The dated feed remains chronological and includes the same display group on relevant activity rows.

`GET /api/v1/records`, `GET /api/v1/feed` and `GET /api/v1/trash-pickup` accept optional `query_address=<street address>` for address-focus comparison. Each returned item then has `address_evidence`, which is `null` if that source record has no eligible explicit address or an object with `source_field`, `source_address`, and `matches_query`. This comparison does not change parcel association or filter records. The MCP `get_parcel_records`, `get_parcel_feed` and `get_parcel_trash_pickup` tools accept the same optional `query_address` argument. API clients should resolve the address and select the City parcel first; the browser does this before displaying an address focus.

## MCP

`/mcp` exposes Streamable HTTP MCP with stateless requests and bearer authentication. It registers `resolve_parcel`, `get_parcel`, `get_parcel_geometry`, `get_parcel_map_context`, `get_parcel_overview`, `get_parcel_records`, `get_parcel_trash_pickup`, `get_parcel_feed`, and `list_sources`, plus source-coverage and matching-method resources. Start with `resolve_parcel`, then `get_parcel_overview`; request geometry, map context or one record group only when needed. `get_parcel_trash_pickup` returns the same address-level records as the REST endpoint without paging through the Property group. The MCP tools call the same service as REST, including ambiguity and partial-source behavior. Point an MCP client at `https://<deployment>/mcp` and send `Authorization: Bearer <individual pilot token>` on each request. Keep this token in the client's private secret store.

## Source coverage

The machine-readable catalog is published in `dist/parcel-source-catalog.json` and returned by `/api/v1/sources`. `live` means the adapter makes a source request when queried; it does not certify source completeness or currentness. `gap` means no direct parcel association has been verified. `paused` means deliberately excluded from collection for now. Runtime source errors appear as `unavailable`, and truncated responses as `partial`. Address-only state business and credential records and manually selected planning documents are not returned as parcel records.

| Group | Live parcel-linked records | Visible gaps |
| --- | --- | --- |
| Property | The complete selected City parcel attribute row plus its building, use, units and assessed fields; City address points and trash pickup zones joined to address points; Vision assessor land, building, subarea, extra-feature, outbuilding and valuation rows | City parcel assessed columns have no verified valuation year or tax balance. A mapped pickup zone does not establish commercial collection eligibility. Assessment subareas do not establish retail lease area. Tax bill and City Clerk land records still lack a verified parcel join. |
| Ownership | City GIS first and second owner and mailing fields; one City parcel sale field set; separately published assessor owner, co-owner, mailing and Ownership History rows; matched Connecticut owner LLC entity, principals, and registered agent | The City and assessor owner names can differ. A single City sale field set and assessor history may omit transfers. Registry principals and agents do not establish beneficial ownership or direct property title. |
| Geography | City zoning code, district category and districts for every intersecting polygon; wards, neighborhoods, and mapped local and State historic districts | Zoning codes do not describe the square footage allocated to a use. Historic district maps are dated 2022 and 2021 and are general reference, not permit determinations. |
| Environment | Connecticut DEEP brownfields inventory rows with an exact published Site Parcel match to City PID or MBLU | The inventory is a February 2026 snapshot, not a statement of current contamination or a complete environmental site search. |
| Representation | Board of Alders roster through an unambiguous ward; city GIS CMT district intersections and provisional GIS contact fields | CMT contact details can differ from the city CMT page and require confirmation. |
| Activity | Live municipal parcel documents, applications, complaints, contacts, licenses, occupants, permits and certificates; LCI Case HQ case metadata; LCI managed lots | Municipal complaint narratives and personal contact fields are omitted. Planning cases, LCI licensing, and other inspection or enforcement feeds need a verified parcel join. |
| Business | Named municipal license and occupant rows attached to the Municity parcel reached by verified MBLU | A license or occupant row does not establish a current tenant or business operation. State credentials lack a verified parcel identifier. |

Meetings, agendas and legislation, budgets and monthly finance reports, census area context, and records on nearby parcels are outside this pilot's parcel record scope. City hosted transit stops are available only as separately labeled nearby map context. CMT meeting schedules are not collected.

The parcel map uses the selected City parcel polygon. Separate map context layers show City address points and zoning polygons intersecting that parcel, plus City hosted CT Transit stops and City mapped metered parking spaces within 400 metres in a straight line from the center of the parcel's mapped extent. The metered spaces toggle starts off because it can contain many points. When no meter points are returned within 400 metres, its toggle is disabled and the reason is shown. Each layer reports its source and last edit date when the service publishes one. A failed layer is `unavailable`, not an empty result. These features are not added to parcel record groups or the timeline. The City meter layer is an inventory of mapped points; it does not establish whether a space is open or its current rules or rates. The City publishes [parking maps](https://www.newhavenct.gov/government/departments-divisions/transportation-traffic-parking/resources/maps), but no current machine-readable City or State loading-zone or parking-availability layer has been verified for this pilot. Neither loading-zone markers nor available-space claims are drawn. See the [metered parking source audit](source-field-audits/metered-parking-map.md).

CMT districts are resolved at request time by intersecting the official parcel geometry with the city's CMT district FeatureServer. Every intersecting district is returned; overlapping districts are marked partial rather than selecting one. The same city GIS layer provides manager, neighborhood specialist and chair contact fields. Those contacts are marked provisional because the city's CMT webpage can differ from the GIS layer. No district shapes or contact roster is stored in this project.

Named municipal business licenses are a compact view of the same live Municity parcel children shown in Activity. The verified MBLU links them to the parcel, and the business group preserves the vendor's license status and recorded address. For parcel 10386, this includes `Weary Hobo LLC aka Bar August` with vendor status `Void`, and a `Bar August` license with status `Issued` and a 2023 expiration date. Both records list `990 State St`; neither independently establishes the historical `3 Edwards St` business address or current operation. No business roster or address alias is stored locally.

The Business group counts City License rows whose published `BusinessName` is empty and points to their full rows under Activity → Licenses. It does not label residential licenses as business licenses. The overview distinguishes named license rows from municipal Occupant rows, since an occupant name and occupancy type do not by themselves identify a business. At parcel 11236 (`20 Eld St`), the four currently returned municipal License rows are residential types and none supplies `BusinessName`; they remain visible in Activity's historical section. The official State Business Registry Master lists `All Day Bar Co. LLC` with billing street `20 Eld St`, but that billing address is not a City parcel identifier or evidence that the entity operated at the parcel. Address-only State entity matches are excluded from the parcel Business group.

The State Licenses and Credentials dataset is official, but credential addresses do not carry a verified New Haven parcel identifier. It remains a gap. The former Keys On Kites address-only association at parcel 24641 remains excluded.

For an LLC named as the City parcel owner, the Ownership group checks the live [Connecticut Business Registry Master](https://data.ct.gov/Business/Connecticut-Business-Registry-Business-Master/n7gp-d28j). It requires the full legal name, billing street (including any unit number), city and five-digit ZIP to match the City parcel's published owner name and mailing fields. Common punctuation, whitespace and street suffix spelling are normalized for comparison. The State result must be unique among the queried literal legal-name variants; if the assessor card is available and names a different owner, the link is blocked. If those results are ambiguous, truncated, time out or have no matching mailing address, all State owner LLC sources are `unavailable` and no State row is attached to the parcel. Other registry spelling variations remain uncovered. State entity status and formation date are entity facts, not a date or proof of parcel acquisition.

Only after that match does the API query the official [State Principals](https://data.ct.gov/Business/Connecticut-Business-Registry-Principals/ka36-64k6) dataset with its published `business_id = Master.id` and the [State Agents](https://data.ct.gov/Business/Connecticut-Business-Registry-Agents/qh2m-n44y) dataset with `business_key = Master.id`. The Agents dataset's older `business_id` is not used for this join. The API exposes principal names and published business-address fields, and separately exposes the registered agent's published service phone, email and business address. It omits agent residence and mailing fields. These are distinct registry roles: a principal can be a member, manager or other listed party, and a registered agent receives service for the LLC. Neither role is relabeled as a beneficial owner or a direct owner of the real estate. At parcel 10386 (990 State St), the current official City and State owner fields match `990 STATE STREET ASSOCIATES, LLC`, ALEI `0659195`; the State currently lists `The Robert Megna Trust` as a principal and `ROBERT MEGNA` as its agent. This example is a live source check, not a locally stored affiliation table. Results are queried on demand with the pilot's five-minute cache.

The official [Municity parcel 13396](https://www.municityconnect.com/#/app/NewHavenCityCT/entity/Parcel/13396) has PrintKey `241 0234 00100` and legal address `181 CROWN ST`. The city GIS parcel 13791 has the same MBLU and lists `181 CROWN ST`. Municipal permit `B-21-02020` is attached to that parcel and describes work at Cask Republic, with legal address `181 CROWN ST`. Neither that parcel record nor the checked city parcel and address-point layers identifies `179 CROWN ST` as an address for this parcel. The resolver therefore does not attach a search for `179 Crown St` to parcel 13791. Cask Republic appears only in the original municipal work record, not as a parsed business listing.

For parcel 24641, the municipal vendor response omits the Complaint and License categories. The municipal source is partial, and the Business group does not claim that no municipal license exists.

The municipal parcel lookup reads Document, Application, Complaint, Contact, License, Occupant, Permit and Certificate arrays from the public vendor response after matching its parcel PrintKey to the city's MBLU. A returned empty array has count zero; an omitted category has count `null` and displays as “not returned.” Categories over the 500-record display limit are marked truncated, and the displayed count covers only returned public records. Missing or truncated categories make the source partial. Public, nondeleted document records include a link to the vendor file when its URL is available on the verified media host. The API does not download or store files. Complaint records omit narrative; contact records omit phone, email and mailing address. Occupant rows expose only name, business name, occupancy type, recorded address, source-reported inactive flag and creation date. Deleted rows and rows with a conflicting Parcel_ID are excluded. A missing inactive flag is not treated as active status. Permit and application child rows expose source-reported status and work description; the on-demand [work detail lookups](source-field-audits/municity-permits.md) follow an exact permit or application ID to full source fields, fees, review tasks, inspections where returned, public documents, contact roles, communication metadata and source flags. A permit includes its explicitly linked application. A returned inspection row does not establish complete inspection coverage. The [cross-source permit search](cross-source-permit-search.md) filters a bounded municipal permit type through City neighborhood geometry and exact parcel MBLU joins, with explicit completeness limits.

The assessor adapter checks the exact PID on the live City of New Haven Vision card before returning any fields. Its Ownership record carries the primary owner, a published co-owner when supplied, and separate mailing-address lines. Its Ownership History table supplies individual owner, sale price, book and page, instrument, certificate and sale date rows. Those rows appear in the Ownership group and, when dated, in the timeline. The City GIS parcel's separate `parcel-sale` record supplies its one published sale date, price, book and page field set. Four assessor valuation tables supply current and historical appraised and assessed rows by valuation year; a valuation year is not converted into an event date. A `$0` sale price is displayed literally, with no market-value interpretation. The same card can publish building count, year built, living area, land size, use code, model, style and stories. Single-building summary facts are extracted only from unique labels; multiple building sections remain separate. Each readable Building Sub-Areas table supplies individual code, description, gross area, living area and its published building section. Totals are excluded from individual rows, and unreadable source values are preserved as published and marked partial. Separate property records carry the card's land-use and land-measure rows, building-section summary and attribute rows, Extra Features rows, and Outbuildings rows. An assessor zone is not a City zoning determination, and a subarea does not by itself establish a retail lease area. Undated assessment facts stay out of the dated timeline. The assessor's published rows may not be a complete deed chain. City Clerk land records remain a gap until a direct parcel join is verified. See the [assessor field audit](source-field-audits/assessor.md) and [City parcel field audit](source-field-audits/city-parcels.md) for checked fields and remaining coverage limits.

The City hosted [local historic district](https://services6.arcgis.com/AWSPcxcHO7OnZlnu/ArcGIS/rest/services/New_Haven_Local_Historic_Districts/FeatureServer/5) and [State historic district](https://services6.arcgis.com/AWSPcxcHO7OnZlnu/ArcGIS/rest/services/New_Haven_State_Historic_Districts/FeatureServer/1) polygons are queried by parcel intersection. The [Connecticut DEEP brownfields layer](https://services1.arcgis.com/FjPcSmEFuDYlIdKC/ArcGIS/rest/services/Brownfields_Final_2025/FeatureServer/0) is queried for New Haven rows and then filtered to an exact PID or MBLU match against its published `Site_Parce` field. Address and point proximity never create a brownfield parcel record. These sources are retrieved at request time and share the existing short cache. No historic boundary or DEEP inventory row is turned into a current permit or environmental determination.

LCI is queried at request time by the assessor PID. The adapter requires matching PID and address on the public property page and returns only case number, type, status, filed date, listed case fine, and link. A case section is considered checked only when the page supplies a recognizable table or explicitly says zero cases; missing sections make the response partial, and a page with neither is unavailable. It does not fetch case-detail pages, complaint narratives, or attachments. A listed fine is source-reported and should be confirmed before use. The real-estate tax and land-record sources expose links and honest `unavailable` statuses until a permitted live lookup and parcel join are verified. SearchIQS is not scraped. The API stores no parcel dataset, snapshots, or change history; successful lookups use the existing five-minute runtime cache.

## Verification and limits

`npm test` covers private access, ambiguous parcel IDs, selected polygon conversion including holes and multiple parts, REST/MCP geometry parity, missing and projected geometry, multiple intersecting zoning and historic district records, exact DEEP parcel matching, municipal child categories, assessor building facts and ownership and valuation tables, exclusion of address-only state records, partial feed behavior when an upstream fails, and MCP initialization. `npm run build` validates the original directory and emits the pilot source catalog and locally bundled map library. Public source terms, historical coverage, and field freshness still need source-level review.
