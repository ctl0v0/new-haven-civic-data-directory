# City GIS parcel layer field audit

Checked November 18, 2026 against the official [New Haven Parcels FeatureServer layer](https://gis.newhavenct.gov/server/rest/services/Hosted/New_Haven_Parcels_Authoritative_Parcel_Viewer/FeatureServer/0). The live layer published 76 attribute definitions. Four exact parcel features were inspected: 20 Eld St (PID 11236, OBJECTID 979), 990 State St (PID 10386, OBJECTID 20011), 181 Crown St (PID 13791, OBJECTID 19764), and 867 Whalley Ave (PID 24641, OBJECTID 2767). The latter is the selected City parcel previously reached from an 869 Whalley Ave address search. These samples do not prove that every nullable field is populated citywide.

The resolver selects a City parcel ID and OBJECTID. `loadParcel` requests `outFields=*` and the polygon from the live layer, and checks that exactly one selected feature has that parcel ID and OBJECTID. The `parcels` Property record already returned every published attribute, but the page showed only a few fields and its source link pointed to the layer rather than the selected feature. The raw record now links to an exact OBJECTID query. This audit does not add a parcel database or a retained source snapshot.

| Field family | Published source fields | Before this audit | Current API and MCP treatment |
| --- | --- | --- | --- |
| Identity and address | `objectid`, `parcel_id`, `account_number`, `mblu`, map/block/lot/unit components, `property_address`, property city/state/ZIP, street components, `parcel_location` | All in raw Property record; parcel ID, address, MBLU and account also in search/summary | Raw fields retained with an exact source link. Address, MBLU and account are visible on the Property row. The layer's `property_zip` is shown only as published; for 20 Eld it is `6511` while its mailing ZIP is `06511`. |
| Owner and mailing | `owner_name_1`, **`owwner_name_2`**, `co_line`, `mail_address`, `mail_city`, `mail_state`, `mail_zip` | First owner and mailing fields structured; code read nonexistent `owner_name_2`, so published second owners were omitted | Both owner names and the separate `co_line` source field appear in Ownership. `co_line` is not treated as an owner name. The returned `owner_name_2_source_field` records the City's misspelled field name. On 20 Eld the City layer names `ROSENSHINE URI` in `owner_name_1` and `MORFORD KENNETH L` in `owwner_name_2`; these are source fields, not a current title determination. |
| Sale | `sale_date`, `price`, `book`, `page` | Date on the raw parcel row entered the timeline; price and deed reference required opening raw fields | One `parcel-sale` Ownership record retains all four fields, preserves a numeric zero price, and supplies the dated City parcel sale event when the date parses. The undated raw parcel record no longer duplicates that event. This is one field set, not complete ownership history. |
| Use, building and units | `use_code`, `zone`, `year_building_built`, `total_land_area_acres`, `units_commercial`, `units_residential`, `units_condo` | Raw record; only building year, commercial units and use code were highlighted in the former summary | A `parcel-assessment` Property record exposes all seven published values. The parcel `zone` is kept separate from the City's zoning polygons. Unit fields are reported as source fields, without inferring occupied or rentable spaces. |
| Assessed values | `total_assessed_bldg_value`, `total_assessed_bldg_xf_value`, `total_assessed_improvements`, `total_assessed_land_value`, `total_assessed_land_outbldg`, `total_assessed_extra_features`, `total_assessed_parcel_value_x`, `total_assessed_parcel_value_y` | Raw record only | All eight columns are in `parcel-assessment` under their source names. The x/y suffixes are not resolved into one canonical total; no valuation year or tax balance is inferred. On 181 Crown the source's extra-feature columns report different values, so neither is silently substituted for the other. |
| Administrative and geometry-related | `gis_tag`, `globalid`, `rem_pid`, `nh_status`, `nh_comments`, ward, `census_tract`, image file fields, projected x/y, `SHAPE__Area`, `SHAPE__Length`, suppression flags, map cuts and rotation | Raw record | Raw values remain available. `nh_status` is not a business or occupancy status. The published census-tract field is not used to reintroduce census context. Image paths are not constructed into document links. Map geometry comes from the selected polygon returned in longitude and latitude, without interpreting the raw x/y or shape measurement units. |

The layer metadata reported `editingInfo.lastEditDate` of February 4, 2026 during this check. That is a layer-wide edit date, not a date for each parcel row. The layer does not establish the valuation year of its assessed columns. The assessor's separate current and historical valuation tables remain separately labeled sources; a difference between City parcel and assessor values is left visible. The GIS sale fields and assessor Ownership History may describe the same transfer, but they retain separate source identities.

The `parcel-sale` event appears in the dated feed; the undated City parcel and assessment records remain in the Property group. All records are fetched on request with the pilot's short cache. The private review page temporarily hides “At a glance” while its content is being defined and uses tighter record spacing. The source catalog and property schema validator now check the published misspelling `owwner_name_2` explicitly.
