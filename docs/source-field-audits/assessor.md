# Vision assessor card field audit

Checked November 18, 2026 against official live New Haven Vision cards for [990 State St, PID 10386](https://gis.vgsi.com/newhavenct/Parcel.aspx?pid=10386), [181 Crown St, PID 13791](https://gis.vgsi.com/newhavenct/Parcel.aspx?pid=13791), and [867 Whalley Ave, PID 24641](https://gis.vgsi.com/newhavenct/Parcel.aspx?pid=24641). The 20 Eld St card (PID 11236) did not respond to the source check, so no completeness claim is made for that card. These are samples of the public assessor schema, not a citywide census of card variants.

The parcel adapter verifies the card's `MainContent_lblPid` against the selected City parcel ID before returning any assessor data. It fetches on request with the pilot's short cache; this audit adds no stored parcel records.

| Published field family | Assessor card controls | Before this audit | Current parcel API and MCP treatment |
| --- | --- | --- | --- |
| Parcel identity and top valuation | `lblLocation`, `lblMblu`, `lblAcctNum`, `lblPid`, `lblGenOwner`, `lblGenAssessment`, `lblGenAppraisal` | Raw card fields; current valuation tables also modeled | Raw card fields remain; four current/history valuation tables remain separate records. |
| Owner of record | `lblOwner`, `lblCoOwner`, `lblAddr1` | Primary owner alone in Ownership; co-owner and mailing address only in raw card text | Primary owner, co-owner when supplied, and separate published mailing lines in the Ownership record. `lblLabelCoOwner` is only the field label; it is not a name. All three checked cards had an empty `lblCoOwner` value. |
| Sales | `grdSales`, plus top `lblPrice`, `lblBp`, `lblSaleDate`, `lblInstrument` | Ownership History rows modeled; top fields in raw card | Ownership History rows remain modeled and dated in the timeline. Top fields remain on the raw card; they repeated the latest table row on the three checked cards. |
| Land use and measures | `tblLandUse`, `tblLand`: use code/description, assessor zone, neighborhood, alternate land appraisal, category, size, frontage, depth, land values | Flattened into raw card text; only a few fields promoted to `building_facts` | Two ordered, source-labeled tables in one `assessor-land` record, plus explicit use code, use description, assessor zone and neighborhood code. The assessor zone is not substituted for the City zoning layer. |
| Building sections | `ctl*_lblHeading`, `ctl*_tblBldg`, `ctl*_grdCns`: year built, living area, replacement cost, percent good, construction, use, systems and other attributes | Building facts from unique labels only; construction table flattened into at most 1,000 characters of raw card text | One `assessor-buildings` record per published building section, with every readable summary and attribute row, its label and value, and building/section number when published. The card's `lblBldCount` is now read so multiple buildings are not summarized as one. |
| Building subareas | `ctl*_grdSub`: code, description, gross area, living area | Individual rows modeled, but section identity was table order alone | Existing rows now also carry the published building and section heading and parsed numbers when available. |
| Extra features | `grdXf`: code, description, size, value, assessed value, building number | Flattened raw table text | Individual `assessor-extra-features` records. A published “No Data” table yields `no_records`; a missing or unreadable table is `unavailable`. |
| Outbuildings | `grdOb`: code, description, subcode, subdescription, size, value, assessed value, building number | Flattened raw table text | Individual `assessor-outbuildings` records with the same empty versus unavailable distinction. |

On 990 State St the card publishes a `RET` Retail Area row with 6,637 gross and living square feet, as well as an `APT` Apartment row and an unfinished basement row. On 867 Whalley Ave it publishes separate office, retail, porch and unfinished basement subareas. These are assessor descriptions and areas, not verified lease areas or zoning permissions. On 181 Crown St the Extra Features table includes a sprinkler row; on 867 Whalley Ave the Outbuildings table includes a paving row. Those previously lacked individual parcel records.

All new records appear in the Property group of `GET /api/v1/records` and the matching MCP tool. The co-owner appears in the Ownership group when the card supplies a value. These facts have no event date and do not enter the dated timeline. Assessor sales remain in that timeline. Unknown or changed table layouts are reported as unavailable or partial rather than treated as empty.

For the next source audit, compare live source fields with structured records, raw-only fields, UI visibility, pagination, date semantics and source coverage. Add a field to the parcel API only with its original source label and a verified parcel join; do not infer occupancy, ownership shares, tax balances, or present building use from assessment labels.
